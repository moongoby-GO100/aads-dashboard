# WP03 RESULT — 채팅 runtime·공통 SSE·status single-flight

작성 기준일은 2026-09-12이며, 이 문서는 [검증·롤아웃 계획의 WP03](../VERIFICATION-AND-ROLLOUT.md)에 대한 프런트엔드 구현 기록이다. 기준은 WP02와 통합 문서 동기화가 포함된 `origin/main`의 `3c889a1`이다.

## STEP 0 기존 구현 조사 및 변경 분류

| 분류 | 기존 접점과 판정 |
| --- | --- |
| 유지 | `/chat` workspace/session, 실제 `app/chat/ChatInput`, IME·첨부·음성·모델/역할, tool/thinking, artifact/document, 알림, WP02 viewport controller와 기존 표시·복구 helper를 유지한다. |
| 유지 | v1 `GET /chat/messages`, `streaming-status`, execution replay, `last-response` 및 `POST` send/interrupt/stop/resume/regenerate endpoint와 payload를 유지한다. 프런트엔드의 직접 DB 접점은 없으며 이번 작업에서 API·DB schema를 바꾸지 않는다. |
| 수정 | `page.tsx`의 direct/replay/resume/regenerate 네 reader가 `ChatEventStreamDispatcher`를 사용한다. status poll은 완료 뒤 다음 tick을 예약하는 `SingleFlightStatusScheduler`로 바꾸고, status의 `last_event_id`는 server high watermark로만 관찰한다. 메시지 merge에는 명시 version/completeness/render key 정책을 연결한다. |
| 신규 | `features/chat/domain`의 execution/transport/view 타입·terminal reducer·message version reducer·capability adapter, `transport`의 WHATWG parser·v1/v2 event adapter·snapshot adapter, `runtime`의 session-scoped controller·single-flight scheduler와 결정 selftest를 추가한다. |
| 삭제 | 네 reader의 `TextDecoder + split("\\n") + data: ` 인라인 parser와 event-id 선반영, status의 `setInterval(async ...)`를 제거한다. 호출처는 같은 endpoint/handler를 공통 dispatcher에 연결하므로 기능·API 삭제는 없다. 롤백은 route 연결과 신규 runtime/test 파일을 함께 되돌리면 된다. |

지시서에 개별 파일로 열거되지 않은 `src/app/chat/types.ts`, `tests/chat-modernization/*`, baseline hash 변경은 v2 additive field를 view model에 보존하고 T05~T09/T21/T36 및 기존 WP00 source gate를 새 공통 parser 구조에 맞추기 위해 필요하다. 기존 구현 전체를 교체하지 않고 네 framing prefix, cursor 소유권, status timer와 message merge 경계만 이관했다.

## 구현 계약

| 항목 | 구현 | 추적 |
| --- | --- | --- |
| 상태 분리 | `ChatRuntimeSnapshot`이 `execution`, `transport`, `view`, `cursors`를 독립 slice로 소유한다. EOF/abort는 transport만 reconnect/disconnect하고 execution terminal을 만들지 않는다. | C07, FR05, INV03/04, T05 |
| 공통 framing | WHATWG line 규칙, CR/LF/CRLF, comment, BOM, multi-data, `data:` no-space, split UTF-8, id/event/retry를 한 parser가 처리하며 네 entry가 같은 dispatcher를 생성한다. | C10, FR06, ADR06, T06 |
| cursor | JSON/schema/scope/dedupe와 reducer 적용이 성공한 frame만 `lastAppliedEventId`를 이동한다. status 광고는 `serverHighWatermark`, atomic snapshot 보장은 `snapshotCoversThroughEventId`에 별도 저장한다. | C09/C19, FR07, INV06, T07 |
| identity/version | `render_key`는 최초 mount identity를 보존한다. 같은 version의 minimal/preview는 full을 축소하지 않고, 더 높은 decimal-string version은 짧은 정상 편집도 반영한다. | C11/C13, FR08, INV09, T08 |
| status | async interval을 제거하고 한 요청 완료 후 다음 tick을 예약한다. AbortSignal, session epoch/current guard, request revision 및 decimal revision 역행 guard를 통과한 응답만 handler가 적용한다. | C08/C26, FR09, T09 |
| terminal/capability | stop 접수는 `stopping`이며 terminal과 다르다. terminal reducer는 old owner/revision callback과 다른 terminal 전이를 거부한다. 기존 action lock은 capability adapter를 통해 같은 동작을 유지한다. | C05/C18, FR21, INV07, T21 |
| 호환/flag | v1 event를 기본 adapter로 보존하고 v2 envelope와 unknown additive event를 비파괴 처리한다. `NEXT_PUBLIC_CHAT_RUNTIME_V2`/`NEXT_PUBLIC_CHAT_PROTOCOL_V2`와 서버 capability는 세션 진입 때 snapshot으로 고정하며 열린 세션에서 hot-swap하지 않는다. | C10/C21, FR36, INV15, T36 |

## 남은 인수 범위

실제 Chromium/Firefox/WebKit의 half-open fetch stream, 브라우저 online/offline 전환, A→B→A와 background tab, v1/v2 서버 교차 버전, 실제 2초 status 응답, Redis trim/snapshot-required, stop/done 경쟁은 아직 실행하지 않았다. 실제 iOS/Android, IME·보조기기, 운영 DB/Redis/provider도 이번 결정 fixture의 범위가 아니다.

## 롤백

신규 `domain/runtime/transport` 모듈과 WP03 tests를 제거하고 `page.tsx`의 네 reader framing 및 status interval/cursor adapter를 WP02 기준으로 되돌리면 된다. 기존 endpoint, v1 payload, 저장 데이터, DB schema 변경은 없다. 열린 세션 중 adapter 전환은 하지 않고 새 세션 진입 또는 reload 경계에서만 이전 경로를 선택한다.
