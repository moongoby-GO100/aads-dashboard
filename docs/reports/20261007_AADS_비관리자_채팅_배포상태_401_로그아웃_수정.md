## 1. 원인

`ChatArtifactPanel.tsx` 가 패널이 보일 때마다 `chatApi('/ops/deploy/status')` 를 호출한다(4초 후 1회 + 15초 주기). 서버 라우트(`app/api/ops.py:570`)는 `require_internal_admin` 이라 `is_admin=false` 토큰에는 401 을 준다. `api.ts` 의 `chatApi` 는 모든 401 을 세션 만료로 보고 `handleChat401()` 을 호출해 토큰을 지우고 `/login?...reason=session_expired` 로 보낸다. 그래서 비관리자는 `/chat` 진입 직후 로그아웃됐다. 이 호출은 bcff94c(2026-09-14)부터 있었다.

## 2. STEP 0 기존 구현 분류

| 대상 | 분류 | 비고 |
|---|---|---|
| `api.ts` `chatApi` 기본 401 → `handleChat401()` | 유지 | 옵션 없는 호출은 동작 동일 |
| `api.ts` `chatApi` 3번째 인자 `{ softAuth }` | 신규 | true 면 401/403 을 로그아웃 없이 `ChatApiError` 로 던짐 |
| `api.ts` `ChatApiError`(status 보유) | 신규 | 기존 `Error` 의 하위 클래스. 메시지 형식(`"<status>: ..."`) 유지 |
| `api.ts` in-flight 합치기 | 수정 | softAuth 호출은 별도 키(`soft:`)로 분리 — 전역 401 처리가 다른 호출끼리 약속을 공유하지 않도록 |
| `ChatArtifactPanel.tsx` `loadDeployStatus` | 수정 | `getMe()` 로 비관리자 확인 시 호출 생략, 호출은 softAuth, 401/403 은 안내문으로 표시 |
| `DeployStatusCard` error 박스 | 유지 | 기존 에러 박스에 안내문 표시 |
| 서버 코드 | 변경 없음 | |

삭제 항목 없음. 롤백: 두 파일의 변경을 되돌리면 된다(다른 파일 영향 없음).

## 3. 동작

- `getMe()`(캐시됨, 추가 네트워크 없음)가 `is_internal_admin` 이 아님을 알려주면 `/ops/deploy/status` 를 호출하지 않고 패널에 "배포 상태는 관리자만 볼 수 있습니다" 를 표시한다. 서버가 요구하는 조건과 같은 `is_internal_admin` 기준(채팅 페이지의 `isInternalAdmin` 과 동일)이다.
- 관리자 여부를 확인하지 못하면(`getMe` null) 호출은 하되 softAuth 로 보내 401/403 이 로그아웃으로 번지지 않고 같은 안내문이 표시된다.
- 다른 모든 채팅 API 의 401 은 기존대로 `handleChat401()` 전역 로그아웃.
