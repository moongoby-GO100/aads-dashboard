2. `PROBE_PATCHED` 없이 `python3 scripts/probe3.py desktop` / `mobile` 로 S1~S11 을 다시 재고, 3절 표의 "수정 후" 열과 비교한다(스모크 S9 120px 는 3회 이상).
3. 결과를 이 문서의 새 리비전으로 기록한다.

## 8. 남은 위험

- 경로 1은 타이밍 경합이라 재현율이 낮다(수정 전 10회 중 2회). 수정 후 0회지만, "재발 0" 을 통계로 보장할 표본은 아니다.
- 수정 후 수치는 압축 청크에 같은 변경을 손으로 적용한 사본의 결과다. 칩 연결은 컴파일된 컴포넌트 캐시 때문에 전역 콜백 1개로 대신했다. `jumpToPendingApproval` 변경은 측정하지 않았다. 실제 빌드에서 다시 재야 한다(7절).
- `markUserGesture` 는 아래 방향 휠에서도 `manual` 로 바꾼다. 맨 아래에서 더 내려갈 곳이 없는 휠은 scroll 이벤트가 없어 `manual` 이 남는다(S7 시작 mode=manual). 기존 동작이고, 자동 이동이 아니라 "안 따라감" 쪽이라 이번에는 바꾸지 않았다.
- 레이아웃 축소와 같은 프레임에 있었던 진짜 사용자 스크롤은 follow 판정에서 빠진다. 다음 scroll 이벤트에서 다시 판정되므로 영향은 한 이벤트로 끝난다.
- 실제 iOS Safari 가상 키보드는 headless 로 재현할 수 없다. S10 은 뷰포트 축소로만 근사했다.
- `ai-streaming-<세션>` 키 중복 자체는 남아 있다. 복원은 이제 안전하다. 다만 같은 값이 React key(`page.tsx` 메시지 목록 `key={msg.render_key || msg.id || idx}`)로도 쓰여 중복 key 경고·재사용이 생길 수 있고, 이것은 이번 범위 밖이다(별도 과제 권장).
