# AAG 아키텍처 상태 화면 검증

- document_key: `aag-dashboard-verification`
- 대상: AADS 대시보드 `/aag`, GO100 AAG 운영 목표의 V11-7
- 상태: 구현·로컬 검증 완료, 운영 배포·사용자 인수 미완료

## 사용자 흐름

CEO·운영 담당은 운영·서버 메뉴의 아키텍처 상태로 진입해 GO100을 기본 대상으로 확인한다. 최신성·마지막 적재·결함·검사 범위를 각각 판정하고, 같은 스냅샷으로 고정된 결함 목록과 근거를 조회한다. 프로젝트·브랜치 필터를 복원한다. 내부 식별자는 접힌 근거 상세에서 확인한다.

401은 기존 로그인 경로로 복구하고, 403은 권한 안내를 표시한다. 미스캔과 미배포 404를 구분하며 네트워크 오류에는 다시 시도를 제공한다. 다시 스캔은 승인 안내만 제공하고 실행하지 않는다. 마지막 적재는 DB 적재 기록이며 원격 스캔 성공을 뜻하지 않는다.

## 로그인 간 캐시 격리

원 개발 커밋의 영구 상태 캐시가 프로젝트·저장소·브랜치만으로 구분되어 로그인 변경 뒤에도 재사용되는 것을 실제 TypeScript의 합성 저장소 테스트로 재현했다. 운영 미배포 코드의 결함이며 실제 사용자 정보 유출이 확인된 것은 아니다.

후속 수정은 운영 상태의 영구 캐시를 제거했다. 같은 화면에서 이미 조회한 값만 메모리에 유지하고, 새 페이지에서는 이를 복원하지 않는다. 권한 거부 뒤에는 운영 값·결함·상세를 지워 후속 네트워크 오류에서 되살아나지 않게 한다. 필터 복원은 유지한다.

## 실행한 검증

| 검증 | 실제 결과 | 범위 |
|---|---|---|
| `npm run typecheck` | exit 0 | 수정 후 TypeScript |
| 변경 TypeScript ESLint | exit 0, 경고 없음 | 화면·로직·selftest |
| `npm run selftest` | 16/16 파일 통과 | 기존 회귀 포함 |
| Playwright 브라우저 회귀 | 12 passed, 0 failed | 첫 진입·필터·스냅샷 고정·권한·오류·캐시·모바일 |
| 모바일 캡처 보강 후 재실행 | 3 passed, 9 skipped | 모바일 사례만 선택 실행 |
| 화면 대비·터치·키보드 | 검사 통과 | 390px 모바일, 실제 캡처·ARIA 포함 |

브라우저 대상은 로컬 `http://127.0.0.1:3921/aag`이다. 실제 Playwright에서 모든 API 응답을 fixture로 교체하고 합성 로그인 토큰을 사용했다. 실제 Vault 사용자 로그인·운영 API·운영 배포 검증은 아니다. 캡처와 ARIA는 `/tmp/aads-aag-privacy-captures`에 있으며 첫 진입과 상세 캡처를 구분했다. 테스트 서버는 종료했다.

## 남은 인수

운영 API·대시보드 배포, 실제 사용자 AAG 조회 권한 연결, 운영 URL 로그인·모바일·오류 복구 확인과 최소 5분 P0/P1 관찰은 남아 있다. 실제 스캔은 장중 회피 규칙을 지킨다. 운영 상태 영구 캐시를 다시 도입하려면 사용자·테넌트·권한 검증을 별도로 설계해야 한다.

문서는 동일 키의 정본 초안으로 등록하며 승인 여부는 DB 정본을 따른다. 전체 목표나 마일스톤 완료로 간주하지 않는다.

## 승인 범위 최종 검수

승인 원본 `f1cf65c`의 변경을 최신 원격 기준 `3c4a6a3`에 충돌 없이 반영했다. 추가 검수에서 서버가 미관측 영역 때문에 `partial`로 판정해도 숫자가 모두 채워지면 검사 완료와 결함 없음이 정상으로 표시되는 문제를 재현했다. 전체 수치와 서버의 `complete`/`full` 판정이 함께 있어야 범위가 입증되도록 교정했고, 검사 수가 전체 수보다 큰 경우도 거부한다.

- 대상 `http://localhost:3929/aag`, 합성 로그인·fixture API. 데스크톱·390px 모바일 및 신규 회귀 캡처는 `/tmp/aag-reviewed-b749-captures`에 보존했다. 운영 로그인이나 운영 화면 검증을 대신하지 않는다.
