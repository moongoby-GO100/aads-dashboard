# PRD: 채팅 문서링크 우측 아티팩트 패널 열람 v1.0

작성일: 2026-09-08 KST
상태: CEO 승인 후 구현 반영
대상: AADS Dashboard `/chat`

## 1. 질문 및 지시 파악

채팅 응답에 포함되는 문서, 리포트, HTML 목업, 코드 파일 링크를 클릭했을 때 새 탭으로 이탈하지 않고 채팅창 오른쪽 아티팩트 패널에서 바로 확인할 수 있게 한다.

외부 웹사이트 링크는 기존처럼 새 탭으로 열고, AADS 내부 문서 링크만 패널 열람 대상으로 제한한다.

## 2. 목표

1. `/docs?project=...&base_path=...&file_path=...` 링크는 기존 프로젝트 문서 API로 파일 내용을 읽어 우측 패널에 표시한다.
2. `/reports/...`, `/exports/...`, `/static/reports/...`, `/static/docs/...` 링크는 같은 사이트 정적 문서로 fetch 후 우측 패널에 표시한다.
3. `.html`은 `html_preview`, 코드성 파일은 `code`, 일반 문서는 `report`, 바이너리/이미지/PDF는 `file` 타입으로 기존 아티팩트 패널 렌더러를 재사용한다.
4. 모바일에서는 기존 아티팩트 오버레이를 열어 같은 흐름으로 확인한다.

## 3. 계획

신규 백엔드 API나 신규 아티팩트 탭을 만들지 않고, 현재 배포된 기능을 재사용한다.

| 레이어 | 구현 방향 | 이유 |
|---|---|---|
| 링크 정규화 | `MarkdownRenderer`에서 내부 문서 링크를 클릭 인터셉트 대상으로 판정 | 기존 markdown 렌더 경로 전체에 적용 가능 |
| 문서 로딩 | `page.tsx`에서 `/project-docs/content` 또는 정적 fetch 호출 | 기존 인증/문서 API 재사용 |
| 패널 표시 | `setArtifacts`, `setArtifactTab`, `setArtifactMode`로 임시 아티팩트 삽입 | DB 저장 없이 즉시 미리보기 가능 |
| 모바일 | `setMobileOverlay("artifact")` 재사용 | 별도 모바일 UI 없이 기존 패널 UX 유지 |

## 4. 실행순서

1. `MarkdownRenderer.tsx`의 링크 렌더러에 `onDocumentLinkClick` 핸들러를 추가한다.
2. `page.tsx`에 문서 링크 클릭 핸들러를 추가한다.
3. 모든 메시지 렌더링 경로와 스트리밍 복구 버블에 핸들러를 전달한다.
4. 링크 클릭 시 로딩 아티팩트를 먼저 표시하고, fetch 성공 후 실제 타입으로 교체한다.
5. 실패 시 같은 패널에 오류와 원본 링크를 표시한다.

## 5. 결과

| 링크 유형 | 결과 |
|---|---|
| AADS `/docs?...` | 우측 패널에서 문서 내용 확인 |
| AADS `/reports/*.html` | 우측 `미리보기` 탭에서 HTML 확인 |
| AADS 코드 문서 | 우측 `코드` 탭에서 내용 확인 |
| AADS 일반 문서 | 우측 `보고서` 탭에서 내용 확인 |
| 외부 URL | 기존처럼 새 탭 유지 |
